## Исправления по результатам проверки

1. Браузерный тест заполнял email на старой странице login до завершения перехода. Добавлено ожидание URL и заголовка; ошибка не скрыта повторными кликами.
2. Повтор учебного действия держал старое замыкание с версией состояния. Теперь хранится описание действия, а повтор использует текущие функции/версию и прежний request ID, когда результат неопределён.
3. Ошибки загрузки/сохранения цели проходят безопасный фильтр; загрузка имеет timeout.
4. У пустого маршрута добавлена ссылка на диагностику; пустой список не создаётся.
5. Форма восстановления сохраняет ввод при сбое, переводит фокус на ошибку, блокирует дубль во время запроса и объясняет неопределённый результат отмены.
6. Страница о данных дополнена описанием нового реестра и связи событий с аккаунтом; анонимность и автоматическая очистка не обещаются.

Первый live doctor получил HTTP 401 на profiles-schema. Read-only SQL подтвердил SELECT у service_role и authenticated. Отдельный REST-запрос `limit=0` вернул 200; повтор полного doctor прошёл. Причина единичного ответа не установлена; права и ключи не менялись, автоматический повтор для сокрытия ошибок не добавлялся.
