Источник: `MVP_AI_Mentor_Plan_September_2026.docx`, пункты 4.1–4.3. Код реализован и локально проверен. Полная приёмка требует сценария в браузере ниже. Следующий этап DOCX — 5, первое подключение AI.

## Что реализовано

| Пункт | Результат |
| --- | --- |
| 4.1 Интерфейс | Meet your mentor, Message, AIMessage, UserMessage, ChatInput, SendButton, Typing; ввод с клавиатуры и телефона, состояния ожидания и ошибок |
| 4.2 Информация | Жизненная ситуация, одна цель, имеющийся опыт, работа/учёба, время по неделе, интересы, хобби/спорт, удобный способ обучения, размер занятия, текущие проекты; отдельно имя |
| 4.3 UX | Вопросы по одной теме, свободный текст, пропуск личных тем, просмотр итога, исправления, возврат к разговору и явное сохранение |

Обычное знакомство — подготовленный диалог без AI; это написано на экране. Введённые слова переходят в профиль без автоматических выводов. Имя и одна цель обязательны; остальные темы можно пропустить. Для длины занятия доступны быстрые варианты и ввод 10–120 минут; если тема пропущена, остаётся прежнее значение или 25 минут по умолчанию, видимое в итоговом профиле. Недельный график хранится текстом: приложение не создаёт календарь. Самооценка опыта не повышает mastery.

Существующий свободный разговор с AI сохранён как отдельный вариант для настроенного провайдера. Он использует реальный API, streaming, историю и извлечение кандидата профиля; Typing показывается во время запроса. Без AI-ключей этот вариант не предлагается. Само наличие данного кода не означает приёмку этапа 5.

Перед сохранением виден итог со всеми полями. Кнопка «Исправить профиль» открывает редактор. До подтверждения значения — черновик на текущей странице; переход к итогу и обратно сохраняет его, перезагрузка может удалить. Во время начатого подготовленного разговора браузеру передаётся предупреждение о закрытии страницы. Это не постоянная история и не защита всех внутренних переходов.

После подтверждения preview сохраняет профиль только в этом браузере; аккаунт — через существующий API в Supabase. После входа его можно править в «Профиль». Ошибки сохранения оставляют черновик на экране; кнопки блокируются на время запроса. Версия профиля защищает от перезаписи изменений другой вкладки. Старые профили читаются с пустыми новыми полями, без сброса имени, цели и аватара.

## Обновление в твоей единственной папке Aporia

Эта среда не подключена к твоему Windows-компьютеру. Патч применяет изменения в `C:\Users\Sinon\OneDrive\Рабочий стол\Aporia`; вторую папку проекта создавать не нужно.

Обновление рассчитано **поверх этапа 3**: исходный `f33236a` плюс ранее выданный `aporia-stage3.patch` либо те же файлы после твоего коммита. Зависимости не изменились. Новая SQL-миграция для этапа 4 не нужна; уже настроенные Auth и миграции 001–004 остаются основой сохранения.

1. Останови `npm run dev` через Ctrl+C.
2. Скачай выданный `aporia-stage4.patch` в «Загрузки» под этим именем.
3. Открой терминал PowerShell в VS Code и выполни **весь блок**:

```powershell
& {
    $ErrorActionPreference = 'Stop'
    Set-Location -LiteralPath 'C:\Users\Sinon\OneDrive\Рабочий стол\Aporia'
    $stage4Patch = Join-Path $HOME 'Downloads\aporia-stage4.patch'
    if (-not (Test-Path -LiteralPath $stage4Patch -PathType Leaf)) {
        throw 'Download aporia-stage4.patch first.'
    }
    git apply --check --ignore-space-change --ignore-whitespace $stage4Patch
    if ($LASTEXITCODE -ne 0) {
        throw 'Patch conflicts with local files. Stop and share the error.'
    }
    git apply --ignore-space-change --ignore-whitespace $stage4Patch
    if ($LASTEXITCODE -ne 0) { throw 'Patch was not applied.' }
    npm run verify
    if ($LASTEXITCODE -ne 0) { throw 'Verification failed. Stop and share the error.' }
    npm run dev
}
```

Проверка совместимости идёт до применения. При конфликте блок остановится: не применять `--reject`, не делать reset и не заменять проект архивом. Если изменения уже применены, повторять патч не нужно. Эти команды не выполняют commit, push, staging, удаление файлов, замену `.env.local` или запись в облачную базу. Выполнение SQL и повторная установка зависимостей для этого обновления не требуются.

4. После `Ready` открой [знакомство без аккаунта](http://localhost:3000/preview/onboarding). Если Next выбрал другой порт, используй адрес из терминала. Для настоящего аккаунта — [onboarding](http://localhost:3000/onboarding): завершённый профиль перенаправляется на dashboard, поэтому для полного знакомства используй новый аккаунт, не удаляя старые данные.

## Проверки и приёмка

В рабочей копии прошёл `npm run verify`: ESLint без предупреждений, 47 unit/SQL-тестов, production build с TypeScript, HTTP-проверка маршрутов и учебного цикла, Auth HTTP. Новые тесты покрывают все темы знакомства, пропуски, ограничения, исправления, совместимость старого профиля; HTTP-тест сохраняет все поля через API, выходит, входит и читает их в редакторе.

Auth HTTP использует настоящее Next.js-приложение и локальный тестовый сервис Supabase-протокола. Это не удалённая база пользователя. Chromium в этой среде отсутствует; браузер не стартовал, поэтому ниже **не отмечено как пройденное**:

- [ ] Desktop и телефон: открыть знакомство, начать, отвечать по одному вопросу; проверить отправку кнопкой/Enter, перенос Shift+Enter и пропуск личной темы. Горизонтальной прокрутки нет, все действия доступны.
- [ ] Пройти все темы, проверить итог. Исправить цель, работу/учёбу и хобби; вернуться к разговору и вновь к итогу — правки остаются.
- [ ] Указать неверную длину занятия: ошибка понятна, ответ не теряется. До подтверждения профиль не меняется.
- [ ] Подтвердить профиль в preview, открыть «Профиль» и перезагрузить: значения и прежний аватар остаются. Проверить общую паузу и reduced-motion; консоль браузера без ошибок приложения.
- [ ] В реальном аккаунте повторить сохранение, выйти и войти: все поля восстановились, открыт dashboard. Для другого аккаунта эти данные недоступны.
- [ ] Перед сохранением в аккаунте отключить сеть: успех не показывается, правки остаются; вернуть сеть и повторить. При конфликте версии исправления не перезаписывают более новый профиль.
