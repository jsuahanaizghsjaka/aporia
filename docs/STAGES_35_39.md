## 35. Отзыв после занятия

После завершённого урока и в его истории есть «Было полезно?» — да/нет и необязательный комментарий до 500 символов. Комментарий можно заполнить до оценки или отдельно сохранить после неё. Сохранённую оценку можно изменить; ошибка не стирает введённый текст.

Хранение: `public.learning_states.data.sessionFeedback`, поля `session_id`, `helpful`, `note`, `at`. Одна актуальная запись на занятие. Это часть существующей атомарной записи учебного состояния: проверенная сессия пользователя, RLS, optimistic version check и request ID. Новый SQL DDL не нужен; старые состояния получают пустой массив при чтении, старые отзывы о сложности сохраняются отдельно.

Сервер отклоняет отзыв о чужом, отсутствующем, незавершённом занятии или диагностике. Отзыв не создаёт evidence и не меняет mastery. Не делаем вид, что клик «полезно» — доказательство знаний. Read-only аудит: `supabase/checks/stages35-39.sql`, без текста отзывов и личных полей.

## 37. Публикация

Использовать один согласованный существующий Vercel-проект, не создавать новый дубликат. Production должен использовать текущую Aporia1, а не старую Aporia. Обязательны пять настроек: Supabase URL, publishable key, server-only secret key, OpenAI API key, model. Секреты не записываются в документацию и Git. Новые переменные для 35–39 не нужны.

Выбран пользователем `aktan2/aporiax1`, основной адрес `https://aporiax1.vercel.app`. `vercel.json` запускает `npm run doctor && npm run build`: ошибочная/пустая конфигурация останавливает облачную сборку, а не выпускает демо вместо приложения. `doctor` здесь не вызывает AI. URL и publishable key имеют тип Config; серверные ключи — Secret. Обычный `npm run verify` по-прежнему собирает локально без реальных ключей.

После успешного релиза добавить точный HTTPS `/auth/callback` в Supabase Redirect URLs, сохранить локальный callback, установить production Site URL. Для recovery используется тот же callback с параметром `next`. Не добавлять wildcard ко всем чужим preview-адресам. Сертификат, HTTP-статус и работа auth проверяются на опубликованной версии отдельно от локальных тестов.

Если ключ когда-либо был опубликован в чате/репозитории, считать его раскрытым и заменить у провайдера. Не переносить заведомо раскрытые ключи в новый production. Publishable key не является серверным секретом; secret/service_role/OpenAI key являются.

## 38. Проверки

Перед локальными HTTP/browser тестами остановить обычный dev-сервер Aporia — Next.js не допускает две dev-копии в одной папке.

```powershell
npm run verify
if ($LASTEXITCODE -ne 0) { throw "Проверки не прошли" }
npm run test:browser
if ($LASTEXITCODE -ne 0) { throw "Браузерные проверки не прошли" }
npm run doctor -- --live
npm run build
```

Узкий прогон: `npm run test:release:browser`. Он проверяет HTTP + PostgreSQL/RLS и интерфейс на 1440/390 px. Тестовые пользователи и ответы AI локальные, платный AI и настоящие аккаунты не затрагиваются. Доставка email и ответы реального AI этим не подтверждаются.
