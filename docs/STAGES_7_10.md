Совместимость: старые профили остаются в `profiles.data`, новые поля получают безопасные значения по умолчанию. `src/lib/profile/memory.ts` представляет полную схему плана с массивами интересов, увлечений и предпочтений. Прежние текстовые поля интерфейса преобразуются при чтении и подтверждении; массовой перезаписи профилей нет. Свободное пожелание из знакомства отделено от активной цели. AI не меняет профиль и не завершает знакомство самостоятельно.

Диагностический набор формируется сервером из проверенного банка (41 задача), не случайной генерацией LLM. Для маленькой coding task проверяется ограниченный арифметический поднабор Python на десяти входах: переменная n, целые, скобки, +, -, *, //, %. Допускаются эквивалентные решения. Циклы, импорты, вызовы и произвольные Python-программы не исполняются; ограничение явно указано в задании. Это не полноценная Python sandbox.

Карты навыков нельзя изменять из браузера или генерацией AI. PostgreSQL пересчитывает производные показатели в той же транзакции, что и сохранение учебной памяти. Уже имеющиеся ответы при миграции сохраняются и формируют карту; повторная миграция восстанавливает только производные строки.

## С самого начала: установить обновление

1. Скачай **aporia-stages7-10-update.zip** из текущего ответа. Распакуй в `C:\Users\Sinon\Downloads\aporia-stages7-10-update`. Сразу внутри должны быть `apply-update.mjs`, `update-manifest.json`, `patches`, `START_HERE.md`. Это пакет обновления, а не вторая папка приложения. Старые `windows-ready` и `desktop-update` архивы не нужны.
2. В VS Code открой только существующую Aporia на рабочем столе. Сохрани открытые файлы. В терминале с работающим `npm run dev` нажми **Ctrl+C**.
3. Открой PowerShell в этой же VS Code и выполни:

```powershell
Set-Location "$HOME\OneDrive\Рабочий стол\Aporia"
node "$HOME\Downloads\aporia-stages7-10-update\apply-update.mjs"
if ($LASTEXITCODE -ne 0) { throw "Обновление остановлено. Пришли сообщение об ошибке; следующие команды пока не выполняй." }
```

Пакет проверяет все изменения до записи и делает резервную копию заменяемых файлов внутри Aporia. Поддерживаются известные снимки main `f33236a`, после этапов 3, 4 и сохранённого этапа 6. Неизвестные правки не перезаписываются. Если сообщит о несовместимости — пришли вывод и `git status --short`; не используй reset, принудительную замену или `--reject`. Ключи, пользовательские файлы и история Git не удаляются.

4. После успешного обновления, в той же папке:

```powershell
npm ci
if ($LASTEXITCODE -ne 0) { throw "npm ci не завершён. Сначала устрани ошибку установки." }
npm run verify
if ($LASTEXITCODE -ne 0) { throw "Проверки не пройдены. Пришли первую ошибку." }
```

При EBUSY останови именно dev-сервер Aporia, закрой процессы, использующие её node_modules, и временно приостанови синхронизацию OneDrive. Затем повтори `npm ci`. Не запускай dev после неудачной установки: ошибка «next не найден» является её следствием. Изменять ExecutionPolicy для этого Node-установщика не нужно.

## Подключить данные

1. Открой свой проект в Supabase. Убедись, что миграции 001–005 уже выполнены. Начальные миграции повторно поверх базы не запускай. Если этап 6 ещё не установлен в базе, сначала выполни `supabase/migrations/202609120005_onboarding.sql` по инструкции этапа 6.
2. В SQL Editor выполни **всё содержимое** `supabase/migrations/202609130006_goals_and_skills.sql`. Эта миграция создаёт цели и дерево навыков, триггеры, защиту доступа и переносит существующие свидетельства в карту.
3. Выполни `supabase/checks/stages7-10.sql`: `skill_count=9`, `invalid_active_goal_owners=0`, `users_without_eight_skills=0`, оба триггера включены. Проверка только читает данные, не выводит личные поля.
4. В локальном окружении должны быть настройки Supabase (URL, публичный и серверный ключи), `OPENAI_API_KEY` и `OPENAI_MODEL`. Модель должна поддерживать Responses API, streaming, strict function calling и structured outputs JSON Schema ([официальная документация](https://developers.openai.com/api/docs/guides/structured-outputs)). Поддержка ограничений схемы зависит от модели; fine-tuned модели здесь не проверены. Новые переменные для этапов 7–10 не требуются. Значения ключей не присылай в чат.
5. `npm run doctor -- --live` проверяет конфигурацию и доступность прежних сервисов; новую схему дополнительно проверяет SQL из пункта 3. Эта команда не заменяет полноценный пользовательский сценарий.

## Открыть и проверить результат

```powershell
npm run dev
```

Открой **http://localhost:3000**. Настоящий сценарий — после входа. Новый аккаунт попадает в `/onboarding`, завершённый — в `/dashboard`. Для дизайна без сервисов открой **http://localhost:3000/preview**; там данные сохраняются только в текущем браузере, AI не вызывается. Старый сайт Aporia Studio этим пакетом не обновляется.

1. Пройди Lesson 0, исправь итог и подтверди профиль. Открой `/profile`, запроси «Уточнить профиль из знакомства». Проверь, что предложение не сохранилось само; перенеси его в форму, исправь работу, часы, заметки, очисти образование и сохрани.
2. Выйди и войди снова. Поля должны восстановиться. Спроси ментора о своём графике: он должен учитывать актуальные значения, не выдавать удалённое поле за сохранённый факт.
3. В блоке цели запроси уточнение пожелания, измени критерии, по желанию укажи дату, нажми «Подтвердить цель». После reload остаётся одна подтверждённая цель.
4. Пройди девять заданий `/diagnostic`; после первого можно закрыть страницу и войти снова — продолжение со второго. Оценивается ответ, не нажатие кнопки и не самооценка.
5. Открой `/roadmap` и `/progress`: восемь направлений, предварительные показатели и дата практики. Повторный вход сохраняет результаты. Другой аккаунт не видит твою цель, профиль и показатели.

Дополнительный автоматический браузерный прогон (останови dev перед ним):

```powershell
npx playwright install chromium
npm run test:browser
```

Автотесты используют локальные тестовые Auth/AI и PostgreSQL/PGlite; настоящие аккаунты и платную модель не трогают. `npm run verify` намеренно собирает без настоящих ключей. Для публикации необходима отдельная `npm run build` с твоим окружением.
