# Aporia: обновление этапов 11–16

Источник нумерации — `MVP_AI_Mentor_Plan_September_2026.docx`. Один профиль, одна активная цель, только Python backend. Этот пакет включает прежний код 1–13 и продолжение 14–16. Он не является подтверждением готовности твоей облачной базы.

## Что реализовано

| Этап | Код |
| --- | --- |
| 14.1–14.5 | Единая миссия для dashboard и урока: профиль/цель, roadmap, mastery, последние занятия/ошибки, проект и время. Приоритет: незавершённое занятие → просроченное повторение → текущий навык маршрута → доступный навык. Выбор 5–120 минут; теория + практика + применение укладываются в бюджет. |
| 15.1–15.7 | `learning_sessions`, Start Session, короткая теория, проверяемое задание, повторные попытки, применение к проекту, история и продолжение после входа. Учителю передаются профиль, цель, навык, mastery, ошибки, время и состояние проекта. |
| 16.1–16.7 | Серверная цепочка Learn: ASK → HINT_1 → HINT_2 → EXPLAIN → PARTIAL_SOLUTION → FULL_SOLUTION. Неверный ответ продвигает на один уровень. Сохраняются attempts и hints_used; повтор запроса не начисляет прогресс. |

AI выбирает **из проверенных вариантов** объяснения и задания на применение. Он не пишет произвольное решение внутри активной практики. Оценка ответов и следующие действия определяются сервером, а не текстом модели. Без AI доступен явно обозначенный подготовленный урок. Если запрос AI не удался, урок не создаётся автоматически: можно повторить запрос либо самостоятельно выбрать подготовленный режим.

Произвольный Python-код не исполняется. Применение к проекту сохраняется как заметка; длина заметки и просмотр теории не повышают mastery. Сохранённый ранее Help Mode оставлен совместимым: он разрешает прямой переход к последнему уровню помощи, учитывая потерю самостоятельности. Разработка новых функций этапов 17+ в этот пакет не входит.

## 1. Обновить только существующую папку

Не используй старые архивы и `update-windows.ps1`. Скачай **aporia-stages14-16-update.zip** в «Загрузки». Сначала останови `npm run dev` через Ctrl+C и закрой другие процессы именно этого проекта. При EBUSY приостанови синхронизацию OneDrive; не завершай все Node-процессы компьютера вслепую.

В PowerShell VS Code выполни блок ниже. Строки `PS ...>` и символы приглашения `>>` копировать не нужно.

```powershell
$project = "C:\Users\Sinon\OneDrive\Рабочий стол\Aporia"
$archive = Join-Path $HOME "Downloads\aporia-stages14-16-update.zip"
if (-not (Test-Path -LiteralPath "$project\package.json")) { throw "Папка Aporia не найдена" }
if (-not (Test-Path -LiteralPath $archive)) { throw "Новый ZIP не найден в Загрузках" }
$unpack = Join-Path $env:TEMP ("aporia-update-" + [guid]::NewGuid().ToString("N"))
Expand-Archive -LiteralPath $archive -DestinationPath $unpack
node "$unpack\install.mjs" --project "$project"
if ($LASTEXITCODE -ne 0) { throw "Обновление остановлено. Пришли текст ошибки" }
Set-Location -LiteralPath $project
npm ci
if ($LASTEXITCODE -ne 0) { throw "Установка зависимостей не завершена" }
npm run verify
if ($LASTEXITCODE -ne 0) { throw "Проверки не пройдены. Пришли первую ошибку" }
```

Распакованная папка — временный пакет установки, не второй рабочий проект. Все изменения устанавливаются в указанный `$project`. Установщик проверяет хеши, сохраняет заменяемые файлы в `.aporia-backups/before-stages14-16-*` внутри проекта, не удаляет посторонние файлы, не трогает `.git` и `.env.local`. Старые пользовательские правки в заменяемых исходниках остаются в резервной копии: при наличии важных собственных изменений сравни их с новой версией до коммита. Частичный сбой копирования требует повторного запуска и сохранения резервной копии. `restore.json` перечисляет заменённые и добавленные файлы.

PowerShell на твоём Windows отсюда не выполнялся. Установщик проверен через Node на кириллическом пути и с CRLF; это не заменяет проверку на компьютере пользователя. Настройки ExecutionPolicy менять не требуется.

## 2. Подготовить Supabase

Не сбрасывай базу и не выполняй весь набор миграций вслепую. Проверь, какие файлы уже применены; перед изменением существующей базы сделай доступную тебе резервную копию. Нужны миграции 001–006 из прошлых этапов. Затем в Supabase SQL Editor выполни **только недостающие** файлы в этом порядке:

1. `supabase/migrations/202609140007_roadmaps.sql` — если ещё не применена.
2. `supabase/migrations/202609150008_learning_sessions.sql` — новая.
3. `supabase/checks/stages11-13.sql`.
4. `supabase/checks/stages14-16.sql`.

В проверке 14–16 ожидаются нули у `duplicate_active_sessions`, `inconsistent_sessions`, `over_budget_sessions`, `assisted_independent_evidence`. `learning_sessions` — фактическое число занятий, включая старые: оно не обязано быть нулём. Миграция добавляет таблицу и заполняет её из сохранённой учебной памяти; аккаунты и профили не удаляются. Не меняй записи `learning_sessions` вручную: сервер обновляет их атомарно с основной учебной памятью и evidence.

Если SQL выдаёт ошибку — остановись и пришли её без секретов. Не удаляй таблицы, чтобы «починить» миграцию.

## 3. Проверить сервисы и открыть результат

`.env.local` сохраняется. Нужны URL и публичный ключ Supabase, серверный ключ для проверенной записи, `OPENAI_API_KEY` и `OPENAI_MODEL`. Значения не отправляй в чат и не коммить. Новых переменных для 14–16 нет.

```powershell
npm run doctor -- --live
if ($LASTEXITCODE -ne 0) { throw "Проверь настройки сервисов" }
npm run dev
```

Открой адрес, который показал Next.js. Обычно:

- `http://localhost:3000/preview` — демонстрация без облачных аккаунтов и без вызовов AI.
- `http://localhost:3000/login` — настоящая учётная запись.
- `/dashboard` — миссия; `/learn` — урок; `/progress` — навыки и история.

Для нового аккаунта нужны Lesson 0 → подтверждение профиля → цель → диагностика. Для существующего всё заново проходить не требуется. Если осталось старое активное занятие, заверши его: следующий Start Session создаст новый трёхчастный урок. Подтверждённый roadmap используется при подборе темы; если его пока нет, используется доступная по предпосылкам тема.

## 4. Ручная приёмка 14–16

1. На `/learn` выбери 5 минут и подготовленный урок. План должен в сумме давать 5 минут.
2. Начни урок: появилась теория. Перезагрузи страницу — должна остаться теория того же занятия.
3. Перейди к задаче. До помощи стадия ASK и полного решения нет.
4. Выбери «Пока не знаю»: появляется HINT_1, ответ можно попробовать снова. Повторяй: HINT_2, EXPLAIN, PARTIAL_SOLUTION, FULL_SOLUTION. Сначала не открывай полный разбор обходными способами.
5. Выйди и войди на этом шаге — стадия и попытки сохранились. Вторая вкладка со старой версией должна получить конфликт, а не перезаписать свежий ответ.
6. Заверши проверку, перейди к применению, запиши пример из проекта и заверши занятие. На `/progress` открой последнее занятие: заметка сохранена.
7. Убедись, что просмотр теории и заметка не дали mastery; подсказки уменьшают самостоятельность; повтор кнопки не создаёт второй результат.
8. Начни следующий урок с AI. Если AI недоступен, должна быть ошибка, а не выдуманное успешное занятие. При работающем AI объяснение подобрано с учётом переданного контекста. Оцени педагогическую полезность настоящей модели отдельно.
9. Проверь dashboard: незавершённый урок важнее повторения; просроченное повторение важнее нового шага маршрута. Будущее повторение не должно считаться просроченным.
10. Повтори основные действия на ширине 390 px, клавиатурой Tab и при выключенном движении. Проверь отсутствие горизонтальной прокрутки и ошибок Console.
11. Аккаунт B не должен видеть историю, заметки, цель и навыки A. Повтори SQL-проверку после занятия.

## 5. Итоговые проверки

Останови dev-server, чтобы он не занимал тестовые порты/сборку:

```powershell
npm run verify
if ($LASTEXITCODE -ne 0) { throw "verify failed" }
npx playwright install chromium
if ($LASTEXITCODE -ne 0) { throw "Chromium installation failed" }
npm run test:browser
if ($LASTEXITCODE -ne 0) { throw "Browser tests failed" }
npm run doctor -- --live
if ($LASTEXITCODE -ne 0) { throw "Service checks failed" }
npm run build
if ($LASTEXITCODE -ne 0) { throw "Build failed" }
```

`verify` изолирован от настоящих ключей; он использует локальные тестовые Auth/AI и PostgreSQL. `doctor --live` — только проверка подключения, не полный урок на реальном аккаунте. Успех моков не подтверждает качество модели, email, RLS в твоём развёрнутом проекте или применённость миграций.

Commit/push не выполняются автоматически. Сначала нужны успешные команды, SQL-проверки и ручная приёмка на твоём окружении. При ошибке пришли первую ошибку и название команды, не `.env.local`.
