# Этап 6 — AI Lesson 0

Актуально на 13 сентября 2026. Нумерация строго из `MVP_AI_Mentor_Plan_September_2026.docx`.

## Что исправлено и реализовано

Новый пользователь после signup/login/email callback направляется в `/onboarding`. Все основные приватные страницы проверяют завершение профиля. Строка профиля создаётся триггером при добавлении пользователя в Auth, ещё до подтверждения email. Миграция 005 восстанавливает этот триггер и добавляет отсутствующие строки, сохраняя прежние данные, аватары и версии.

AI получает отдельную инструкцию знакомства и сохранённый черновик. У каждой из 11 тем есть статус: неизвестно, отвечено или явно пропущено. Имя и цель обязательны; остальные вопросы можно пропустить. Сервер проверяет схему обновления, длину полей, размер занятия и наличие цитаты из пользовательского сообщения. Цитата не доказывает безошибочность интерпретации, поэтому итог всегда проверяет человек.

`record_onboarding` записывает очередной шаг. `finish_onboarding` открывает итог только после обсуждения всех тем; преждевременный вызов возвращает следующий вопрос. Черновик и полный ответ записываются одной строкой в `mentor_messages`. Ответ не объявляется сохранённым при сбое БД. Черновик восстанавливается после перезагрузки и повторного входа; AI не меняет `onboardingComplete` или mastery.

Пользователь исправляет итог и нажимает «Всё верно, сохранить». Только после успешной записи открывается `/dashboard` автоматически. Ошибка оставляет правки на экране. Возврат к разговору и открытие того же итога не затирают исправления. Несохранённые ручные правки не обещаются восстановимыми после закрытия страницы. Подготовленное знакомство без AI остаётся доступно.

## Обновить единственную Windows-папку

Доступа к твоему рабочему столу у этой среды нет. Пакет переносит проверенные изменения в существующую папку; вторую рабочую копию приложения создавать не нужно.

1. Скачай **`aporia-stage6-update.zip`** из ответа и распакуй в `C:\Users\Sinon\Downloads\aporia-stage6-update`. Внутри должны лежать `apply-update.mjs`, `update-manifest.json`, папка `patches` и эта инструкция. Старые архивы не используй.
2. Останови сервер Aporia через Ctrl+C в его терминале. Сохрани открытые файлы VS Code. При прежнем EBUSY временно приостанови синхронизацию OneDrive. Не завершай все Node-процессы компьютера.
3. Открой PowerShell в VS Code и выполни:

```powershell
Set-Location "$HOME\OneDrive\Рабочий стол\Aporia"
node "$HOME\Downloads\aporia-stage6-update\apply-update.mjs"
if ($LASTEXITCODE -ne 0) { throw "Обновление остановлено. Не выполняй следующие команды; пришли сообщение об ошибке." }
```

Установщик проверяет имя проекта, корень Git и совместимость всех изменений до записи. В пакете есть варианты для проверенного main `f33236a`, а также для него с применённым этапом 3 или этапом 4. Он не предполагает, что у тебя обязательно один из этих снимков. При неизвестных изменениях, включая отличающуюся версию этапа 5, установка останавливается целиком. Пришли `git status --short` и сообщение установщика; не делай reset и не применяй патч с `--reject`.

Перед записью заменяемые файлы сохраняются в `.aporia-backups/stage6-*` внутри той же Aporia. Папка исключена из Git. При ошибке файловой системы сохрани эту копию и сообщение ошибки. Установщик не удаляет папки, не меняет env, не выполняет npm, SQL, staging, commit или push.

4. После сообщения об успешном обновлении:

```powershell
npm ci
if ($LASTEXITCODE -ne 0) { throw "Установка зависимостей не завершена. Сначала устрани ошибку npm." }
npm run verify
if ($LASTEXITCODE -ne 0) { throw "Проверки не пройдены. Пришли первую ошибку." }
```

Если `npm ci` снова выдаёт EBUSY, останови именно сервер Aporia, закрой использующие её файлы процессы и повтори установку после освобождения блокировки. Не запускай dev после неудачного `npm ci`: отсутствующий `next` — следствие незавершённой установки.

## Supabase и AI

1. Убедись, что миграции 001–004 уже применены к этому проекту. Не выполняй начальную миграцию повторно поверх существующей базы.
2. В SQL Editor этого Supabase выполни содержимое **`supabase/migrations/202609120005_onboarding.sql`**. Её можно выполнить повторно: существующие профили не перезаписываются. Сам установщик SQL не запускает.
3. Выполни read-only `supabase/checks/onboarding.sql`. Ожидается одна строка триггера с `enabled_for_signup=true`, `security_definer=true`; `accounts_without_profile=0`; `onboarding_draft_column_exists=true`.
4. В локальном env должны быть настройки Supabase и серверные `OPENAI_API_KEY`, `OPENAI_MODEL`. Модель должна поддерживать Responses API, streaming и strict function calling. Ключи не отправляй в чат и не добавляй в Git.
5. Проверь настройки callback: `http://localhost:3000/auth/callback` и адрес используемого сайта. Письмо PKCE открывай в том же браузере, где зарегистрировался. Подтверждение в другом браузере этим обновлением не меняется.
6. `npm run doctor -- --live` проверяет доступность настроек чтением; качество ответа и полный сценарий он не подтверждает.

## Посмотреть результат и принять исправления

```powershell
npm run dev
```

Открой **http://localhost:3000**. Внешний старый сайт Aporia Studio этим пакетом не обновляется. `/preview/onboarding` показывает ручное знакомство без аккаунта; AI проверяется после входа в `/onboarding` с настроенными сервисами.

1. Новый тестовый аккаунт: сразу после регистрации строка `profiles` уже существует. Подтверди письмо в том же браузере — должна открыться `/onboarding`.
2. Ответь на пару тем, перезагрузи страницу и нажми «Начать знакомство»: история и недостающие темы восстановятся.
3. Обсуди все темы; личные можно явно пропустить. Итог должен открыться автоматически, но ещё не переводить на главную и не подтверждать профиль.
4. Исправь цель. Вернись к разговору, открой итог — правка остаётся. Подтверди: после успешного сохранения открывается `/dashboard` без дополнительной кнопки.
5. Выйди и войди повторно: остаются исправленная цель и завершённое знакомство. После logout прямой `/dashboard` открывает login. Аккаунт B не видит профиль или разговор A.

Для автоматического браузерного сценария останови dev и запусти:

```powershell
npx playwright install chromium
npm run test:browser
```

Тест использует локальные сервисы, не твои настоящие аккаунты. Браузер установлен отдельно от `npm ci`. После QA запускай dev заново; для облачного релиза нужна отдельная `npm run build` с реальным env, поскольку verify намеренно собирает без ключей.
