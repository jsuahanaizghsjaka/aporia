# Проверка доработки · 8 сентября 2026

## Первая дизайн-доработка · выполнено

- Production build Next.js 16.3.4 и проверка TypeScript: успешно.
- ESLint для src, scripts, tests: без ошибок.
- Семь целевых тестов: UTF-8/CRLF в потоке AI; отказ при оборванном/некорректном SSE; безопасные redirects; проверка Origin; валидация профиля; ограничения загрузки фото; запрет завершения знакомства с пустым именем/целью.
- HTTP-проверка собранного приложения без ключей: восемь защищённых страниц перенаправляют на login; шесть публичных экранов отвечают; неизвестная страница — 404; API отказывает в неавторизованных и межсайтовых запросах; регистрация при отсутствии настройки сервиса возвращает 503.
- Браузер: главный экран и профиль на desktop; адаптивная страница в frame шириной 390px (375px доступного содержимого со scrollbar), без горизонтального переполнения.
- Мобильное меню открывается, переходит в профиль и закрывается после перехода. Доступна отдельная русская кнопка закрытия.
- Смена имени, символа, цвета и формы аватара; явное сохранение; восстановление после reload. Использованы только синтетические тестовые данные, затем возвращены начальные настройки.
- Глобальная пауза отключает движение; video.paused=true, readyState=4. При prefers-reduced-motion CSS отключает анимации, provider не запускает видео. Последний режим проверен по коду: эмуляция media features в доступном браузере не предоставляется.
- Видеофайл загрузился; исходная подпись PI-SLICES сохранена. Снимки в docs/previews.
- В консоли не было ошибок приложения. Обнаруженное предупреждение Next о smooth scrolling исправлено атрибутом data-scroll-behavior. Ошибки расширения браузерной среды и сообщения Fast Refresh не выдаются за ошибки приложения.

## Не проверено на внешних сервисах

В окружении отсутствуют URL/key Supabase и OPENAI_API_KEY/OPENAI_MODEL. SQL миграция подготовлена, но не применена к удалённой БД. Не выполнены реальная регистрация/подтверждение email, изоляция двух удалённых аккаунтов, upload через Storage API, вызов AI и повторный вход с облачной памятью. SQL/RLS отдельно проверены в продолжении ниже. Перед alpha необходим этот интеграционный прогон из README.

Управляемый браузер не возвращает событие filechooser: попытки выбора файла завершились тайм-аутом. Поэтому полный браузерный путь «выбор фото → кадрирование → upload» пока не подтверждён, хотя код обработки, валидация и интерфейс готовы. Профили с символами и локальное сохранение проверены отдельно. Ограничение не обходилось внесением файла в DOM или подменой событий.

## Доступность навыков

Использованы правила репозитория, Next.js, React Best Practices и control-browser; Sites применён только для совместимого внутреннего preview, не для переноса/публикации репозитория. Установленные в исходном проекте навыки сохраняются.

Глобальные design-taste-frontend и impeccable не найдены; их загрузка отклонена автоматической проверкой из-за лимита использования. Получение текущего web-design-guidelines вернуло DisabledError. Полный аудит этими навыками не заявляется. Graphify не смог собрать граф: отсутствуют tree-sitter и networkx; выполнено непосредственное чтение архитектуры, API и продуктовых документов. Изменять навыки или обходить отказ загрузки не стали.

Живой цикл auth/памяти, cross-account RLS/storage, восстановление после сетевого сбоя, фактическая политика Learn/Help, ограничения размера входных запросов на хостинге, email/redirects на production-домене, тест фото в обычном браузере. Учебный цикл этапов 4–5 теперь реализован; актуальная проверка описана ниже.

## Продолжение этапов 4–5

- ESLint и TypeScript/production build успешны после добавления учебных экранов и API.
- `npm test`: 20 тестов, включая 11 сценариев учебного engine и одну комплексную проверку PostgreSQL, помимо прежних 7 тестов и проверки UUID для HTTP-предпросмотра.
- Engine: цель обязательна, одна активная сессия, диагностика без подсказок/повторного старта, все 8 ответов сохраняются, одна диагностика не даёт высокой оценки. Learn проходит стадии, Help допускает прямой разбор, открытое решение не считается самостоятельным.
- Повторный request ID и второй ответ не дублируют evidence; повторная практика до due date не увеличивает оценку, самостоятельное разнесённое повторение создаёт новый сигнал. Миссия учитывает основы, время, незавершённую сессию и due reviews.
- Сохранение произвольного кода, AI-review, просмотр ресурса и отзыв не начисляют mastery. Один активный проект; устаревший AI-разбор не может переписать изменённый черновик. Обзор использует реальное окно последних 7 дней.
- Банк содержит 40 уникальных заданий; все эталоны принимаются, посторонние значения отклоняются. В клиентских chunks не найден проверяемый фрагмент закрытого банка.
- PGlite: обе SQL-миграции выполнены в настоящем PostgreSQL/WASM с минимальной инфраструктурой auth/storage. Два синтетических пользователя изолированы RLS для профилей/учебной памяти/фото. authenticated не может UPDATE learning_states или вызвать commit RPC. service_role пишет через проверку версии; конкурирующая устаревшая запись отклоняется. Лимит 30 AI-запросов проверен отдельно для каждого пользователя. Это тест SQL, не сетевого Supabase SDK/Auth/Storage.
- HTTP production-сборки без ключей: защищённые маршруты, landing/privacy/новые preview-экраны, 404, CSRF/401, отсутствие внешнего AI. Полный POST-цикл: диагностика → практика → идемпотентный ответ → завершение → проект → сохранённый черновик → восстановление состояния.
- Ветка содержит GitHub Actions workflow, повторяющий lint/test/build/HTTP; удалённый запуск CI не заявляется, поскольку push не аутентифицирован.

## Ограничения нового прогона

Браузерный инструмент отклонён автоматической проверкой: лимит использования. Новые страницы практики/проекта/прогресса и landing не прошли desktop/mobile визуальный и интерактивный QA. Прежние screenshots относятся к первой дизайн-доработке. Альтернативный браузер или подмена DOM для обхода отказа не использовались.

Supabase/AI credentials отсутствуют. Новая SQL-миграция не применена к внешней базе; настоящие mentor reply/project review и возврат между устройствами не проверены. Vercel-публикация отклонена автоматическим контролем из-за неуказанного проекта, видимости и аудитории. Конкретный предлагаемый объём и оставшиеся проверки описаны в `docs/RELEASE.md`.

Финальная HTTP-проверка выявила, что добавленный корневой loading boundary превращал серверный redirect в потоковый ответ 200. Корневой boundary убран; индикаторы внутри защищённого layout и учебного provider сохранены. Повторная проверка обязана подтвердить обычный 307 на защищённые маршруты.
