## Фактические ограничения этой сессии

- Пользователь разрешил работу и отправку пользовательских медиа. Push в GitHub всё равно завершился `could not read Username`: отсутствует GitHub-аутентификация. Повторная попытка без новых учётных данных не выполнялась.
- В Vercel видна команда `aktan2`, проекта Aporia нет. Автоматическая проверка отклонила публикацию: не были указаны конкретные проект, видимость и аудитория. Обход через другой сервис не выполнялся. Для нового запроса публикации нужен явно подтверждённый объём из предыдущего раздела и доступный способ записи в Vercel.
- Нет URL/public key/secret key Supabase и OPENAI_API_KEY/OPENAI_MODEL. Общее разрешение пользователя не создаёт эти учётные данные. Ключи следует добавить в окружение проекта, не отправлять в переписку или Git.
- После продолжения локальная диагностика, практика, отзыв, восстановление проекта и мобильная навигация проверены в браузере. Обновлены desktop/mobile screenshots. Локальный путь фото теперь проверен; внешний auth/AI/storage ещё требует проверки.

## Внешний интеграционный прогон до alpha

1. Применить недостающие из трёх SQL-миграций, заполнить env и настроить email/redirects. Сначала выполнить проверки локально с настоящими сервисами. Затем связать ту же Windows-папку с конкретным проектом Aporia в Vercel через CLI; GitHub commit/push для этого не требуется и сейчас запрещён пользователем.
2. Аккаунт A: signup → подтверждение email → login → AI-знакомство → исправление и подтверждение профиля → logout → login. Ментор узнаёт цель без повторного заполнения. Проверить, что недоступный AI даёт ошибку, а не имитацию ответа.
3. Пройти часть диагностики, закрыть вкладку, войти снова, закончить. Проверить запрет подсказок и повторной диагностики. Затем одно Learn-занятие, одно Help-занятие, повторную отправку после разрыва связи и сохранение последнего ответа.
4. Создать один проект, сохранить код, получить настоящий AI-разбор, изменить черновик, проверить пометку устаревшего разбора. Запустить код и тесты проекта отдельно; не выдавать AI-текст за результат запуска.
5. Проверить интервалы повторения на отдельном тестовом проекте, отзывы, подтверждение фокуса и недельный обзор. Не менять часы production-базы ради демонстрации.
6. Аккаунт B: убедиться в отсутствии доступа к профилю, фото, диалогам и учебной памяти A. Попытка отправить свою оценку напрямую в learning_states и вызвать commit RPC от authenticated должна быть запрещена. Проверить реальный Storage API, не только SQL-политику.
7. Открыть две вкладки одного аккаунта, одновременно ответить на вопрос: один ответ принимается, вторая вкладка получает актуальное состояние без второго начисления. После offline/timeout повторить действие.
8. Desktop и мобильный браузер 390px: навигация, поля, клавиатура, длинный код/команды, загрузка/кадрирование/удаление фото, reduced motion, пауза видео, scroll, focus, ошибки в консоли. Проверить собственное фото от выбора файла до сохранения на сервере.
9. После успешного прогона — production env, подтверждённый домен/redirects, контрольный login и один учебный ответ. Зафиксировать deployment ID/commit, логи без секретов и способ rollback в Vercel.

## Alpha, заморозка и beta

- Alpha: 3–5 согласившихся студентов/джунов. Приглашения без отдельной просьбы пользователя не отправляются. Каждому дать один полный цикл и собрать: где остановился, что понял без помощи, где потерял данные, насколько понятен следующий шаг. Форма проблемы — `.github/ISSUE_TEMPLATE/alpha-feedback.yml`.
- Блокирующие дефекты: утечка между аккаунтами, потеря принятого ответа, ложное начисление mastery, обход диагностики через приложение, невозможность вернуться в сессию, выдача AI-разбора за выполненные тесты.
- Freeze: после устранения блокирующих дефектов, реального повторного входа/памяти и проверки фото. Зафиксировать commit и не расширять треки/голос/социальные функции.
- Beta: 10–20 пользователей, ограниченный бюджет AI, наблюдение за завершением первого занятия, возвратом к повторению и понятностью фокуса. Публиковать только реальные результаты использования. Калибровать эвристику mastery по самостоятельному решению новых задач.

Alpha, freeze, beta и production QA здесь **не отмечены выполненными**. Готов код и процедура; тестовые участники и внешний выпуск не подменены фиктивными событиями.

## Обновление после 6–8

Перед внешним запуском применить `202609080003_profile_versions.sql`. `npm run verify` проверен локально и собирает вариант без реальных ключей. После заполнения production env нужны `npm run doctor -- --live` и отдельный `npm run build`. Doctor выполняет только чтение и не заменяет пункты внешнего QA выше. Шрифты находятся в npm-пакете и не требуют Google Fonts во время build.

Локальный выбор/кадрирование/сохранение/восстановление фото, повторное сохранение и конфликт вкладок проверены. Облачный Storage и настоящий AI не проверены. Последнее правило пользователя: commit и push делает он сам; автоматическая отправка запрещена.
