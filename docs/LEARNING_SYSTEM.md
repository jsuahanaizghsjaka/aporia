# Учебная система · этапы 4–5

## Границы доверия

Браузер отправляет типизированное действие (ответ, запрос подсказки, следующий вопрос), request ID и известную версию. Он не передаёт доверенный mastery или итоговую учебную память.

`/api/learning` проверяет Origin и реальную Supabase-сессию, читает только запись пользователя, валидирует действие, применяет чистый engine и записывает новую версию через отдельный server-only admin client. База разрешает authenticated только SELECT собственной learning_states. RPC записи доступен только service_role и использует compare-and-swap; конкурентное изменение возвращает 409 вместе с актуальным состоянием. Повтор принятого request ID не создаёт второй результат.

`/api/learning/preview` — отдельный недоверенный демонстрационный контур: проверяет структуру переданного локального состояния, не обращается к Supabase/AI и возвращает результат браузеру. Данные оттуда не импортируются в аккаунты. Web Locks последовательно выполняют запись между вкладками предпросмотра; storage event обновляет другие вкладки.

Банк эталонов импортируется только серверным engine и тестами. Клиент получает текст текущего вопроса и варианты, затем разрешённую подсказку или разбор после ответа. Это учебные проверки, не защищённая экзаменационная платформа: пользователю доступна отдельная демонстрация и внешние источники.

## Состояние

Версионированный JSON включает диагностический статус, сессии, активную сессию, evidence, сроки повторения, один проект с черновиками/разборами, отзывы, подтверждённый фокус и последние ID действий. Есть пределы начального MVP: 1000 сессий, 5000 свидетельств, 1000 отзывов, последние 300 аналитических событий и 200 request ID. При достижении лимита новые соответствующие записи отклоняются, старые учебные ответы молча не удаляются. Перед расширением beta следует вынести историю в нормализованные таблицы и добавить архивирование.

Личность и цель хранятся в profiles; диалоги — mentor_messages; учебная и проектная память — learning_states. AI не может изменять оценки или подтверждённый профиль через текст ответа.

## Mastery и confidence

Для каждого вопроса берутся три последних разнесённых по времени наблюдения. Наблюдение имеет вес 0.6 для диагностики и 1 для упражнения, повторения или контрольного вопроса проекта. Самостоятельность для ASK/HINT_1/HINT_2/EXPLAIN/PARTIAL/FULL: 1, 0.75, 0.5, 0.25, 0, 0.

Пусть M — сумма весов, E — сумма весов верных ответов, умноженных на самостоятельность, D — число разных вопросов.

- mastery = min(95, round(100 × E/M × (1 − exp(−M/4)))); при M=0 — 0.
- confidence = min(95, round(100 × (1 − exp(−M/5)) × min(1, D/3))).

Один верный диагностический ответ даёт 14% mastery с очень низкой уверенностью. Ошибки могут понижать оценку. Это консервативная рабочая эвристика MVP; её ещё предстоит калибровать на реальных учениках, не психометрическая шкала или вероятность профессиональной компетентности.

Просмотр материалов, отправка отзыва, сохранение произвольного кода и AI-разбор без запуска не увеличивают mastery. Контрольный вопрос проекта подтверждает конкретный принцип, а не успешный запуск всего кода. Повтор того же вопроса до due date не создаёт evidence. На назначенном повторении разрешено новое независимое наблюдение.

## Миссия и политика обучения

Приоритет: незавершённая сессия → первая диагностика → просроченное повторение → доступная тема. Доступность темы зависит от 35% mastery в её фиксированной основе. Среди доступных приоритет у подтверждённого фокуса, иначе у минимального mastery. Пользователь может выбрать будущий фокус; интерфейс объясняет, почему недостаточные основы ещё могут иметь приоритет.

Число вопросов на сессию = clamp(floor(dailyMinutes / 8), 1, 3). Это плановый объём, а не утверждение о фактически затраченных минутах. Диагностика всегда включает восемь вопросов, её можно продолжить после возвращения.

Learn последовательно открывает намёки, общий принцип, частичный ход и решение. Help разрешает прямой разбор. В диагностике помощь запрещена в engine. Пока любое учебное задание активно, общий AI-чат отклоняет запрос с 409: помощь доступна в контролируемом интерфейсе занятия. После завершения AI-чат получает ограниченный контекст последних результатов и проекта. Это не обещание, что ученик не сможет найти решение вне приложения.

## Проект и разбор

Одна тема выбирается явно из задач/музыки/тренировок/книг. Подсказка выбора основана на интересах, решение остаётся за пользователем. Каждый этап имеет краткое ТЗ, критерии, редактируемый черновик и контрольный вопрос.

Разбор AI — отдельный authenticated POST, читает сохранённый черновик, расходует общий лимит AI и сохраняет ответ лишь после completed. Повтор неизменённого черновика возвращает уже сохранённый разбор. Версия и точное содержимое черновика защищают от сохранения устаревшего результата. Подпись «без запуска кода» обязательна; выполнение Python, Docker и сторонних команд не реализовано.

## История, обзор и аналитика

Недельный обзор использует последние 7×24 часа и сравнивает текущую оценку с evidence до этого окна. Отзыв hard за последние 7 дней может предложить тему сложной сессии или внешнего материала. Изменение фокуса происходит только после подтверждения. Отзыв о материале сохраняется, но не создаёт искусственный уровень.

Events содержат только name/at: начало/завершение диагностики/занятия, отправка ответа, запрос помощи, открытие источника, выбор проекта, сохранение артефакта, проверка понимания, разбор, отзыв, подтверждение фокуса. Последние 300 на пользователя — оперативная аналитика, не долговечный биллинговый журнал. SQL для сводок не выводит user ID, тексты или фото.
