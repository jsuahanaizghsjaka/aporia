# Этапы 21–23: установка и проверка

Код продолжает пакет этапов 17–20 и включает предыдущие исходники. Единственная рабочая папка пользователя: `C:\Users\Sinon\OneDrive\Рабочий стол\Aporia`. Удалённого доступа к ней у ассистента нет. Коммиты, push и публикация не выполняются.

## Что добавлено

- **21 — Mastery Evidence.** Таблица `mastery_evidence`, типы diagnostic/exercise/quiz/project/review, источник, время, ответ и учёт помощи. Каждое новое наблюдение сохраняет mastery до и после ответа. SQL-оценки навыков строятся из этого реестра в одной транзакции с учебным состоянием.
- **22 — Progress Screen.** Восемь навыков с progress bar, последней практикой и группами «Сильные», «В процессе», «Нужна практика», «Не начаты». Группа зависит от проверенных ответов, не от мнения AI. Есть фильтр и объяснение с источниками.
- **23 — Learning History.** Дата, тема, длительность, результат, изменение mastery, все попытки и отдельная ссылка на занятие. История подгружается порциями по 20 занятий, без потери доступа к более ранним. Просмотр не меняет оценку.

«Сильные» — mastery от 70% при confidence от 45%; «В процессе» — mastery от 35% без достаточной уверенности для сильной группы; ниже — нужна практика. Нет свидетельств — «Не начаты». Это рабочие пороги MVP, не педагогическая сертификация.

Время занятия — интервал от начала до завершения, включая перерывы; оно не объявляется временем активной работы. План и факт разделены. Для ранних записей, в которых не было журнала оценок, точное изменение не выдумывается. Ответ и разница оценки могут быть неизвестны; существующий mastery сохраняется. Тип quiz поддержан реестром, отдельный новый экран квизов в эти этапы не входит.

## 1. Обнови ту же Aporia

1. Скачай `aporia-stages21-23-update.zip` в «Загрузки». Имя должно совпадать с командой, без `(1)`.
2. В терминале запущенного приложения нажми **Ctrl+C**.
3. Открой указанную папку Aporia в VS Code → Terminal → New Terminal → PowerShell.
4. Вставь весь блок целиком. Если появилась ошибка, остановись и пришли её текст без секретов.

```powershell
& {
    $ErrorActionPreference = "Stop"
    $aporiaProject = "C:\Users\Sinon\OneDrive\Рабочий стол\Aporia"
    $aporiaArchive = Join-Path $HOME "Downloads\aporia-stages21-23-update.zip"
    if (-not (Test-Path -LiteralPath "$aporiaProject\package.json")) { throw "Папка проекта не найдена" }
    if (-not (Test-Path -LiteralPath $aporiaArchive)) { throw "Сначала скачай новый ZIP в Загрузки" }
    $aporiaUnpack = Join-Path $env:TEMP ("aporia-21-23-" + [guid]::NewGuid())
    Expand-Archive -LiteralPath $aporiaArchive -DestinationPath $aporiaUnpack
    node "$aporiaUnpack\install.mjs" --project "$aporiaProject"
    if ($LASTEXITCODE -ne 0) { throw "Установщик остановлен" }
    Set-Location -LiteralPath $aporiaProject
    npm ci
    if ($LASTEXITCODE -ne 0) { throw "Зависимости не установлены" }
    npm run verify
    if ($LASTEXITCODE -ne 0) { throw "Проверки не пройдены" }
}
```

Нужен Node.js 22.18+. Установщик проверяет хеши, сохраняет заменяемые файлы в `.aporia-backups/before-stages21-23-*`, не удаляет `.env.local`, `.git` и посторонние файлы. Он не выполняет Git, SQL или npm; команды npm явно указаны выше. Повторная установка одинакового пакета ничего не копирует.

При EBUSY останови сервер Aporia и программы, которые держат её `node_modules`; дождись синхронизации OneDrive. Затем повтори `npm ci`. Исходники и окружение удалять не нужно.

## 2. Выполни только недостающую миграцию 010

Предпосылка: миграции **001–009** уже успешно выполнены в твоём Supabase. Если ещё не применена 009, сначала используй `docs/STAGES_17_20.md`. Не выполняй все SQL-файлы вслепую.

1. Открой проект Aporia в Supabase и сверь его адрес с `NEXT_PUBLIC_SUPABASE_URL` в своём `.env.local`. Ключи не копируй в чат.
2. Слева открой **SQL Editor**, создай новый запрос.
3. Если не уверен, применена ли 010, выполни только проверку наличия таблиц:

```sql
select
  to_regclass('public.learning_states') as learning_states,
  to_regclass('public.user_skills') as user_skills,
  to_regclass('public.learning_sessions') as learning_sessions,
  to_regclass('public.projects') as projects,
  to_regclass('public.mastery_evidence') as mastery_evidence;
```

Наличие таблиц не доказывает, что все предыдущие функции и политики установлены. При неизвестном статусе 001–009 пришли результат для разбора. Если первые четыре таблицы существуют, предыдущие миграции точно выполнены, а `mastery_evidence` равен NULL, нужна 010.

4. В VS Code открой `supabase/migrations/202609220010_mastery_evidence.sql`.
5. Нажми **Ctrl+A → Ctrl+C**. В новый запрос Supabase вставь **содержимое**, а не путь файла. Нажми **Run** и дождись успешного результата. Файл выполняется одной транзакцией.
6. При ошибке остановись. Не удаляй таблицы, не вырезай строки миграции.
7. Открой локальный файл `supabase/checks/stages21-23.sql`, скопируй содержимое и выполни отдельным запросом SQL Editor.

Если `mastery_evidence` уже есть, сначала проверь историю выполнения миграции и запусти checks. Повторять SQL только ради ненулевого количества записей не нужно.

Ожидаемые результаты:

| Поле | Что ожидается |
| --- | --- |
| evidence_rows | Любое неотрицательное число — реальные сохранённые доказательства |
| legacy_evidence_rows | Может быть больше нуля — старые записи без точной истории оценки |
| mismatched_evidence_counts | 0 |
| missing_source_or_time | 0 |
| unsupported_skill_scores | 0 |
| missing_change_history | 0 |
| unprotected_tables | 0 |

Миграция переносит прежние доказательства без поддельных ответов/оценок и сохраняет профили, проекты и версии учебного состояния. Прямое редактирование `mastery_evidence` и `user_skills` из браузера запрещено.

## 3. Проверь и открой результат

До запуска dev-server:

```powershell
& {
    npx playwright install chromium
    if ($LASTEXITCODE -ne 0) { throw "Браузер не установлен" }
    npm run test:browser
    if ($LASTEXITCODE -ne 0) { throw "Браузерные проверки не прошли" }
    npm run doctor -- --live
    if ($LASTEXITCODE -ne 0) { throw "Проверь настройки сервисов" }
}
```

Затем `npm run dev` → `http://localhost:3000/progress`. Для настоящих данных войди в аккаунт и заверши знакомство. `/preview/progress` — отдельная локальная демонстрация, данные которой остаются в этом браузере.

## 4. Ручная приёмка

1. На аккаунте A открой `/progress`. Проверь восемь навыков, полоски прогресса, дату последней практики и фильтр групп. Пустая группа должна показывать объяснение.
2. В навыке открой «Почему такой уровень?» → «Источник и изменения оценки»: видны тип, время, источник, ответ и помощь. У ранних записей возможна честная пометка о недостающей истории.
3. Пройди новое занятие: ошибись в одном ответе, затем исправь его. Вернись к прогрессу. Должен появиться источник с записями изменения оценки, без повторного evidence за ту же задачу той же сессии.
4. В истории открой новое занятие. Сверь дату, тему, результат, длительность и изменение mastery. Длительность включает паузы и может отличаться от плана.
5. Нажми «Открыть занятие». Скопируй адрес `/progress/sessions/...`, обнови страницу. Ответы, попытки и отражение на проект должны сохраниться.
6. Вернись назад. У активного занятия доступно «Продолжить занятие», у завершённого просмотр не начинает новый урок.
7. Открой материалы/историю и оставь отзыв. Это не должно повышать mastery. Изменение может быть отрицательным после реального неверного ответа — это уточнение оценки, не ошибка счётчика.
8. Выйди и войди снова: история и доказательства сохраняются.
9. Войди аккаунтом B и открой скопированную ссылку занятия A. Ожидается «Занятие не найдено в твоей истории», данные A не показываются. Без входа защищённая страница ведёт на `/login`.
10. На телефоне проверь фильтр, раскрытие доказательств и ссылку занятия. Не должно быть горизонтальной прокрутки страницы; управление доступно с клавиатуры.

Локальные проверки используют настоящие обработчики приложения и изолированные Auth/AI/PostgreSQL fixtures. Они не подтверждают состояние твоей облачной базы, Windows или качество настоящей AI-модели. Ошибки присылай без `.env.local` и ключей. Коммит и push — только после твоей приёмки.
