# QA этапов 17–20 · 22 сентября 2026

## Объём реализации

Проверяется cumulative source этапов 1–20 по исходному DOCX, без commit/push и без изменения Windows-папки пользователя из этой среды.

- 17: переключение Learn/Help внутри занятия, сохранение режима и уже показанной помощи.
- 18: 480 воспроизводимых вариантов по восьми навыкам и трём уровням, серверная проверка ответа, история попыток, подсказки и время до ответа.
- 19: план проекта из цели, интересов и подтверждённого уровня; восемь задач; проверка понимания отдельно от сдачи результата.
- 20: чат текущей задачи, контекст кода и решений, ограниченная помощь Learn, прямой разбор Help, подтверждение решений пользователем.

Браузер запускается через `APORIA_BROWSER_EXECUTABLE` в этой среде; на Windows используется обычный `npx playwright install chromium`. Вспомогательный Chromium не добавлен в зависимости проекта. Предупреждения Node о распознавании ES-модулей в TypeScript не приводят к ошибкам проверок.

Проверки работают с настоящими обработчиками Next.js, локальным PostgreSQL/PGlite и изолированными протокольными Auth/AI fixtures. Это проверка приложения и контрактов интеграций, не облачного Supabase и не качества ответов платной модели.

Сценарии включают повтор запроса без дубликатов, конфликты версий, запрет произвольного mastery/time через API, недоступность и ошибочный ответ AI, timeout, лимит запросов, повторный вход и изоляцию двух пользователей. SQL проверяет RLS, запрет прямой записи, атомарный откат, backfill и повтор миграции 009.

## Ограничения и внешняя приёмка

- Генерация упражнений и планов шаблонная, не произвольная генерация кода AI.
- Код пользователя не исполняется. Сдача задачи — сохранённый код + проверка понимания + отчёт пользователя; она сама не повышает mastery.
- time_spent включает паузы, ограничен 7200 секундами и не является оценкой активного внимания. Старым записям время не выдумывается.
- Требуется установка на Windows, применение только недостающей миграции 009 после 001–008 и SQL-проверка `supabase/checks/stages17-20.sql`.
- Реальные Auth/email, Storage, ответы выбранной модели и облачная изоляция двух аккаунтов требуют ручной приёмки по `STAGES_17_20.md`.
- Коммиты, push, публикация и облачные миграции из этой среды не выполнялись.
