# Aporia: перенос в Windows, просмотр и Git

Рабочая копия ChatGPT и `C:\Users\Sinon\OneDrive\Рабочий стол\Aporia` — разные папки. Изменения не появляются на компьютере автоматически. Текущие исходники передаются архивом `aporia-steps-6-8.zip`; он не содержит `.git`, ключей, `node_modules` или результатов сборки.

## Перенести результат

1. Останови dev-сервер этого проекта через Ctrl+C. Сохрани свои открытые файлы.
2. Распакуй архив в отдельную папку. Внутри находится `Aporia` с исходниками.
3. В VS Code открой свой существующий Git-проект, создай ветку `work/steps-6-8` от текущей main (или используй свою уже созданную рабочую ветку).
4. Сравни свои незакоммиченные изменения с архивом, затем перенеси исходники. Сохрани существующие `.git` и `.env.local`. Если ты менял те же файлы самостоятельно, объедини изменения вручную.
5. Очистка, уже выполненная в передаваемом проекте: старые root `desktop-dashboard.png` и `mobile-dashboard.png`, `skills-lock.json`, служебные папки `.agents/skills/graphify` и `.claude/skills/playwright-cli` больше не нужны. Удаляй эти элементы в своей копии только если они всё ещё относятся к прежней поставке; другие локальные материалы сохраняй. `components.json` и настройки VS Code остаются.

В терминале `npm pkg get scripts` должен показать `doctor`, `verify` и `dev: node scripts/dev.mjs`. Это простой признак того, что открыты обновлённые исходники.

## Запуск

Нужен Node.js 22.18+ (либо 24). Из корня проекта:

```bash
npm ci && npm run dev
```

`&&` запускает приложение только после успешной установки. Открой `http://localhost:3000/preview` или порт из вывода терминала. `/` — landing, `/preview` — рабочая локальная демонстрация без внешних ключей. Можно пройти знакомство, диагностику, занятие, проект и редактирование фото.

## Если npm ci выдаёт EBUSY

EBUSY означает, что файл занят. По одному сообщению нельзя установить, какой процесс держит его: это может быть сервер проекта, синхронизация OneDrive, индексатор или антивирус. Ошибка «next не является командой» возникает после незавершённой установки зависимостей.

Останови именно сервер Aporia через Ctrl+C и закрой окна, работающие с его зависимостями. Если блокировка остаётся в OneDrive, поставь синхронизацию на паузу на время установки. Не нужно завершать все процессы node.exe или сразу открывать терминал администратора.

Более устойчивый вариант — отдельная копия вне синхронизируемой папки, например `C:\Dev\Aporia`. Если такого проекта там ещё нет, скопируй туда существующий проект со своей `.git` и локальными изменениями, исключив `node_modules` и `.next`. Открой эту папку в VS Code и выполни `npm ci && npm run dev`. Старую копию сохраняй до успешного запуска новой.

## Проверки и момент commit/push

```bash
npm run verify
```

Команда проверяет код без настоящих ключей: линтер → тесты → сборка → HTTP-цикл. Она не коммитит, не пушит и не публикует приложение.

После переноса, успешного verify и просмотра `/preview` **можно делать commit**, затем push. В Source Control (`Ctrl+Shift+G`) просмотри изменения и добавь проверенные файлы через `+`. Сообщение, если переносишь весь накопленный результат:

```text
feat: complete local learning MVP and harden persistence
```

Если этапы 1–5 уже есть в твоей ветке:

```text
fix: harden profile saves and add release readiness checks
```

После Commit нажми Publish Branch/Push и дождись GitHub Actions. `.env.local`, ключи, `node_modules`, `.next` и временные тестовые файлы в коммит не входят. Force Push для этого не нужен.

## Облачный запуск

Заполни `.env.local` по README и примени ещё не выполненные SQL-миграции по порядку, включая третью `202609080003_profile_versions.sql`. Затем:

```bash
npm run doctor -- --live
npm run build
```

Doctor проверяет только конфигурацию и доступность чтения; для выпуска нужен полный сценарий двумя аккаунтами из `RELEASE.md`. После verify облачную сборку всегда выполняй отдельно с нужными env. Ключи не отправляй в переписку или Git.

## Обновление единственной папки Aporia

Для Windows-обновления в архиве есть `scripts/update-windows.ps1`. Он работает **только** с существующей папкой рабочего стола, сохраняет её `.git` и `.env.local`, очищает `node_modules`/`.next`, затем запускает `npm ci` и `npm run verify`. Commit и push не выполняет.

Перед запуском останови `npm run dev` через Ctrl+C и поставь OneDrive на паузу. После распаковки архива в Downloads выполни в PowerShell:

```powershell
Set-ExecutionPolicy -Scope Process Bypass -Force
& "$HOME\Downloads\Aporia\scripts\update-windows.ps1"
```

Если архив распакован под другим именем, измени только путь перед `scripts`. Когда скрипт сообщит «Готово», в этой же папке Aporia выполни `npm run dev` и открой `/preview`.
