# Установка и приёмка этапов 17–20

## Что реализовано

17. Learn/Help переключается во время занятия и сохраняется. Показанная помощь не исчезает при возврате в Learn.

18. Упражнения генерируются проверяемыми шаблонами: 8 навыков × 3 уровня × 20 вариантов. Сложность зависит от mastery. Сервер сохраняет ответ, correctness, hints_used, skill_id, time_spent и передаёт проверенный результат в Mastery Engine. Произвольный код пользователя не выполняется.

19. Один активный проект из четырёх тем. Предложение учитывает цель и интересы, сложность восьми задач — подтверждённый уровень. План фиксируется при выборе и не переписывается автоматически при изменении цели.

20. Проектный чат получает текущую задачу, сохранённый код, историю и подтверждённые решения. Learn использует проверенные вопросы, Help даёт прямой AI-разбор. AI не закрывает задачи, не меняет mastery и не сохраняет решения без подтверждения пользователя.

Проверка понимания и сдача задачи разделены. Сдача требует сохранённого кода, правильного ответа и отчёта пользователя о проверке. Это самоотчёт, не автоматическое подтверждение успешного исполнения. Правка кода открывает задачу заново. Старые checkpoints остаются проверками понимания, не превращаются в сданные задачи.

time_spent — интервал от открытия задания до попытки, включая паузы, максимум 7200 секунд. Старые записи без времени не получают выдуманное значение. Интервалы повторных попыток нельзя складывать как активное время; они не влияют на mastery.

## 1. Обновление Windows

Рабочая папка одна: `C:\Users\Sinon\OneDrive\Рабочий стол\Aporia`. Нужен Node.js 22.18+. Коммиты и push не выполняются.

1. Скачай `aporia-stages17-20-update.zip` в «Загрузки». Если браузер добавил `(1)`, переименуй файл или исправь путь в команде.
2. В терминале с `npm run dev` нажми Ctrl+C. Не завершай все процессы Node на компьютере.
3. Открой свою Aporia в VS Code → Terminal → New Terminal → PowerShell.
4. Вставь **весь блок целиком**. Он останавливается при первой ошибке. После ошибки не продолжай следующие команды по отдельности.

```powershell
& {
    $ErrorActionPreference = "Stop"
    $aporiaProject = "C:\Users\Sinon\OneDrive\Рабочий стол\Aporia"
    $aporiaArchive = Join-Path $HOME "Downloads\aporia-stages17-20-update.zip"
    if (-not (Test-Path -LiteralPath "$aporiaProject\package.json")) { throw "Папка проекта не найдена" }
    if (-not (Test-Path -LiteralPath $aporiaArchive)) { throw "Сначала скачай архив в Загрузки" }
    $aporiaUnpack = Join-Path $env:TEMP ("aporia-17-20-" + [guid]::NewGuid())
    Expand-Archive -LiteralPath $aporiaArchive -DestinationPath $aporiaUnpack
    node "$aporiaUnpack\install.mjs" --project "$aporiaProject"
    if ($LASTEXITCODE -ne 0) { throw "Установщик остановлен" }
    Set-Location -LiteralPath $aporiaProject
    npm ci
    if ($LASTEXITCODE -ne 0) { throw "Зависимости не установлены" }
    npm run verify
    if ($LASTEXITCODE -ne 0) { throw "Проверки не пройдены" }
}
```

Установщик проверяет целостность архива, заменяет только перечисленные файлы и делает резервную копию заменённых файлов в `.aporia-backups/before-stages17-20-*`. `.git`, `.env.local` и посторонние файлы не удаляются. Сам установщик не выполняет npm, SQL, Git или публикацию. Повторный запуск без изменений ничего не копирует.

При EBUSY останови сервер Aporia, закрой процессы, использующие её node_modules, дождись окончания синхронизации OneDrive и повтори npm ci. Исходники и .env.local удалять не нужно.

## 2. Supabase

Сначала должны быть применены миграции 001–008. Это обновление добавляет **009**. Если 007/008 ещё не выполнены, используй STAGES_14_16.md. Если статус неизвестен, не запускай всё вслепую — пришли результаты проверки для разбора.

1. Открой свой проект Aporia в Supabase. Сверь адрес с NEXT_PUBLIC_SUPABASE_URL, не публикуя ключи.
2. SQL Editor → новый запрос. Этот запрос только проверяет наличие таблиц, он не доказывает наличие всех ограничений и функций предыдущих миграций:

```sql
select
  to_regclass('public.learning_states') as learning_states,
  to_regclass('public.skills') as skills,
  to_regclass('public.learning_sessions') as learning_sessions,
  to_regclass('public.exercises') as exercises,
  to_regclass('public.exercise_attempts') as exercise_attempts,
  to_regclass('public.projects') as projects,
  to_regclass('public.project_tasks') as project_tasks,
  to_regclass('public.project_messages') as project_messages,
  to_regclass('public.project_decisions') as project_decisions;
```

3. Первые три поля должны быть не NULL. Если шесть новых таблиц отсутствуют и 001–008 точно выполнены, открой в VS Code `supabase/migrations/202609210009_exercises_projects.sql`.
4. Ctrl+A → Ctrl+C. Вставь **содержимое файла**, не путь, в новый запрос SQL Editor и нажми Run. Весь файл выполняется одной транзакцией.
5. Если новые таблицы уже существуют, сначала выполни проверку ниже. При частичном наборе таблиц или ошибке остановись и пришли результат; ничего не удаляй.
6. Открой `supabase/checks/stages17-20.sql`, скопируй содержимое, выполни отдельным запросом.

Счётчики exercises, attempts, projects, project_messages, confirmed_decisions могут быть больше нуля после переноса старой истории. Показатели malformed_projects, invalid_submissions, invalid_attempts, invalid_session_modes, unprotected_tables должны равняться **0**.

Новые таблицы записываются атомарно на сервере и доступны пользователю только для чтения своих строк, с RLS. При ошибке SQL остановись, не удаляй таблицы и не пропускай отдельные строки миграции.

## 3. Проверки и запуск

После verify, до запуска dev-server:

```powershell
& {
    npx playwright install chromium
    if ($LASTEXITCODE -ne 0) { throw "Браузер не установлен" }
    npm run test:browser
    if ($LASTEXITCODE -ne 0) { throw "Браузерные тесты не прошли" }
    npm run doctor -- --live
    if ($LASTEXITCODE -ne 0) { throw "Проверь настройки сервисов" }
}
```

verify и браузерные тесты используют изолированные тестовые Auth/AI/PostgreSQL, не платную модель и не облачные аккаунты. doctor не заменяет SQL-проверки и ручную приёмку.

Затем `npm run dev` → `http://localhost:3000/login`. Нужны завершённый профиль, цель и диагностика. `/preview` показывает локальную демонстрацию; настоящий проектный AI-чат там отключён.

## 4. Ручная приёмка

### 17. Learn/Help

1. На `/learn` начни занятие, переключи Learn → Help.
2. В практике запроси прямое решение, вернись в Learn.
3. Перезагрузи страницу: режим сохранён, помощь по-прежнему учитывается.
4. Ответ после полного решения не должен давать самостоятельный mastery.

### 18. Упражнения

1. Проверь навык и сложность нового упражнения.
2. Отправь неверный, затем правильный ответ. Повторная отправка не должна удвоить evidence.
3. На `/progress` открой последнее занятие → «Все попытки»: видны ответы, подсказки и время.
4. Выйди/войди: результаты сохраняются. Просмотр страницы, отзыв и ожидание не добавляют mastery.

### 19. Проект

1. На `/projects` открой «План из цели и уровня», выбери одну тему.
2. Проверь цель и восемь задач. Второй активный проект создать нельзя.
3. Сохрани код и пройди «Проверку понимания». Количество сданных задач пока не меняется.
4. Сам запусти своё решение и тесты. В «Отчёт о проверке» вставь команды, результаты и оставшиеся проблемы без секретов.
5. Нажми «Сдать результат задачи». Счётчик изменится; сам отчёт mastery не повышает.
6. Измени и сохрани код: задача открывается заново, предыдущий разбор помечается устаревшим.

### 20. Проектный ментор

1. Заверши активное занятие, открой чат текущей задачи проекта.
2. В Learn попроси весь проект: должен появиться ограниченный вопрос/подсказка.
3. В Help попроси прямой разбор фрагмента. Приложение не должно заявлять, что исполнило код.
4. Перенеси AI-предложение в черновик решения, исправь и нажми «Подтвердить решение». До этого подтверждённой записи нет.
5. Задай уточнение: сохранённые решения и код передаются в контекст.
6. Перезагрузи страницу и войди снова: переписка, режим, решения сохраняются.
7. При обрыве/отмене вопрос остаётся в форме. Повтор не должен создать дубликат. Если сервер успел сохранить ответ до отмены, он появится после обновления.
8. Во второй вкладке измени проект во время AI-запроса. Старый ответ не должен перезаписать свежие данные.
9. Войди аккаунтом B: проект, чат и решения аккаунта A не должны появиться.

Тестовые аккаунты создавай в своём Supabase. Здесь проверяются локальные сервисы; облачная база и Windows требуют твоей приёмки. Ошибки присылай без .env.local и секретов. Commit/push остаются за тобой после успешной проверки.
