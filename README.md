# Aporia

Персональный AI-ментор для Python backend: один профиль, одна цель, один учебный маршрут. Источник требований — `PRODUCT_CONTEXT.md`, `MVP.md`, `IN_MVP.md`, `NOT_IN_MVP.md`. Номера и порядок этапов задаёт **MVP_AI_Mentor_Plan_September_2026.docx**, текущий статус — `ROADMAP.md`.

Текущее продолжение: **этапы 7–10 DOCX — память профиля, Goals Engine, диагностика и Skill Graph**. Профиль и цель подтверждаются пользователем, девять диагностических заданий создают свидетельства, показатели восьми навыков сохраняются в PostgreSQL. Установка в единственную Windows-папку, миграция 006 и приёмка: [STAGES_7_10.md](docs/STAGES_7_10.md). Локальные тесты не подтверждают качество настоящей модели или состояние твоей базы. Этапы 5–6 сохранены в этом обновлении.

## Локальный запуск

Рабочая Windows-папка: `C:\Users\Sinon\OneDrive\Рабочий стол\Aporia`. Текущее обновление применяется по инструкции этапов 7–10 выше. [START_HERE_WINDOWS.md](docs/START_HERE_WINDOWS.md) сохраняется как прежняя инструкция запуска с другой нумерацией. Commit и push по текущему указанию пользователя не выполняются.

Требуется Node.js 22.18+ (проверено на 24.19), npm.

```bash
npm ci
npm run dev
```

`/` — главная страница, `/preview` — обозначенная локальная демонстрация. В ней работают подтверждение профиля, диагностика, занятия, проектные черновики, история, повторение и отзывы. Профиль, фото и учебная история сохраняются только в браузере. Ответы проверяет сервер приложения по учебному эталону; демонстрация не вызывает AI и не записывает данные в Supabase. Локальные результаты не переносятся в аккаунт автоматически.

Настоящие `/dashboard`, `/profile`, `/onboarding` и учебные страницы требуют входа. Без него приложение перенаправляет на `/login`. Отсутствие внешних сервисов не скрывается под имитацией ответа AI.

Lesson 0 открывается по `/preview/onboarding` без аккаунта или по `/onboarding` после входа нового пользователя. Подготовленный диалог задаёт по одному вопросу, позволяет пропускать личные темы и исправить итог. Он работает без AI и так обозначен. Все темы из DOCX сохраняются в профиле только после подтверждения. Неподтверждённый черновик хранится на странице до её закрытия; сохранённый профиль переживает перезагрузку. Настоящий AI-режим предлагается только при наличии серверной конфигурации.

## Подключение аккаунтов, памяти и ментора

1. Создать Supabase-проект. Скопировать `.env.example` в `.env.local`, заполнить `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (или старый anon key).
2. Добавить **серверный** `SUPABASE_SECRET_KEY` либо старый `SUPABASE_SERVICE_ROLE_KEY`. Он нужен только обработчику проверенных учебных действий. Никогда не добавлять к нему `NEXT_PUBLIC_`, не передавать клиенту и не помещать в Git. Отдельный admin client не использует пользовательские cookie.
3. Выполнить SQL из `supabase/migrations/` **в порядке имён**. Первая миграция создаёт profiles, mentor_messages, лимит AI, RLS и приватные avatars. Вторая — learning_states и атомарную запись версии. Третья — версии профиля и `commit_profile`; прямые записи профиля заменены атомарной проверкой версии. Четвёртая создаёт профиль при регистрации и добавляет недостающие профили существующих аккаунтов, не меняя их данные. Первая рассчитана на новый проект; выполнить только ещё не применённые миграции по порядку. Перед изменением существующей базы проверить конфликты и сделать резервную копию.
4. В Supabase Auth включить email/password, подтверждение email и SMTP для реальных пользователей. Установить Site URL и разрешённые redirect URL: `http://localhost:3000/auth/callback` и `https://<домен>/auth/callback`.
5. Применить пятую миграцию `202609120005_onboarding.sql`: она восстанавливает собственный signup-триггер Aporia, добавляет отсутствующие профили и колонку черновика знакомства. Существующие профили не перезаписываются. Добавить серверные `OPENAI_API_KEY` и `OPENAI_MODEL`. Нужна доступная в аккаунте модель Responses API со streaming и strict function calling.
6. Перезапустить приложение. Переменные `NEXT_PUBLIC_` в production устанавливаются **до сборки**. Проверка значений и применение миграций на внешнем проекте в этой рабочей сессии не выполнены: доступов нет.
7. Пройти живой тест двумя аккаунтами из `docs/RELEASE.md`. Без этого код не считается проверенным production-релизом.

Внешние API-ключи не включены в репозиторий или архив исходников.

## Учебный цикл (ранее реализованный код)

- Подтверждённый профиль → восемь диагностических заданий без подсказок → предварительная оценка восьми навыков.
- Миссия сначала возвращает к активному занятию, затем к назначенному повторению, затем предлагает доступную тему с учётом основ и подтверждённого фокуса. На занятие выбирается 1–3 задания по дневному времени.
- 40 заданий: 8 диагностических, 24 практических, 8 проверок понимания проекта. Это небольшой начальный банк, не полная сертификация Python backend.
- Learn: ASK → HINT_1 → HINT_2 → EXPLAIN → PARTIAL_SOLUTION → FULL_SOLUTION. Help позволяет сразу открыть разбор. Состояние помощи хранится на сервере. Пока занятие активно, отдельный AI-чат не обходит его политику; подсказки доступны внутри задания.
- Оценки меняются по проверенным ответам, с учётом помощи и разнообразия заданий. Просмотр материалов и нажатие кнопок не начисляют mastery. Повтор до срока не добавляет evidence второй раз.
- Повторение: через 1, 3, 7, 14, 30, 60 дней при самостоятельном успехе; ошибка или помощь возвращают интервал к одному дню.
- Один активный проект из четырёх тем, связанных с интересами. Восемь этапов с критериями и сохранением кода. AI выполняет статический разбор без запуска; проверки понимания не подтверждают работоспособность всего проекта и не маскируются под запуск тестов.
- Прогресс и confidence с объяснением последнего сигнала, история занятий, основной официальный материал по каждой теме, отзывы и обзор реальных последних семи дней. Изменение фокуса требует подтверждения пользователя.
- Аналитика хранит имена событий и время, без текста ответов, кода и профиля. Read-only запросы для оператора — `supabase/analytics.sql`.

Алгоритмы, границы доверия и ограничения — `docs/LEARNING_SYSTEM.md`.

## Профиль и AI-память

Аватар: JPG/PNG/WebP до 5 МБ, масштаб и смещение, экспорт 512×512 WebP. В базе хранится принадлежащий пользователю путь, фото — в приватном bucket; показ через временную подписанную ссылку. EXIF исходника не переносится в canvas-экспорт. Сохранение явное.

Чат получает подтверждённый профиль, последние 40 сообщений режима и ограниченный учебный/проектный контекст. Только полный ответ сохраняется как ответ ментора; при сбое можно повторить отправку с тем же request ID. Кандидат профиля из AI требует проверки человеком. Лимит — 30 AI-запросов в час на пользователя, общий для экземпляров приложения. Requests используют `store: false`; это не обещание нулевого хранения у провайдера.

## Проверки

```bash
npm run verify
```

`npm test` проверяет учебный алгоритм, Auth, потоковые ответы AI, критерии знакомства и выполняет все пять SQL-миграций в PGlite (настоящий PostgreSQL в WASM): owner RLS, запрет клиентской записи оценок, private avatars, лимит AI, конфликт версий и создание профиля при регистрации. Это не проверка сетевой Supabase Auth/Storage.

HTTP-этап запускает production-сборку на локальном порту 3101 без ключей и проверяет защищённые маршруты, публичные экраны, Origin, ошибки API и полный локальный цикл с восстановлением состояния. CI повторяет эти проверки в GitHub Actions после отправки ветки.

`npm run dev` принимает аргументы Next.js. `scripts/dev.mjs` также переводит `--host` в `--hostname` для внутренней визуальной проверки. Сборка и production используют стандартный Next.js.

## Готовность окружения

```bash
npm run doctor
npm run doctor -- --live
```

`doctor` читает `.env` с тем же приоритетом, что production-сборка Next.js, и показывает только названия проверок и результаты. Код 1 означает, что конфигурация неполная или проверка не прошла. `--live` делает только GET-запросы: настройки email Auth, наличие колонок профиля/занятий без чтения строк, приватность avatars и доступность указанной модели. Он не регистрирует пользователей, не применяет SQL, не загружает фото и не вызывает платную генерацию. Успех этих проверок не подтверждает полный облачный цикл.

`npm run verify` запускает lint, 58 тестов, build, HTTP-учебный цикл, `test:auth` и `test:ai` последовательно. Перед запуском остановить dev-сервер. Реальные ключи исключены: тесты используют локальные сервисы, настоящее приложение, PKCE и cookies, сохраняют все поля Lesson 0 и читают их после входа. Они не отправляют письма и не проверяют удалённый Supabase или качество настоящей модели. `npm run test:browser` отдельно проверяет знакомство в Chromium на desktop/mobile; сначала выполнить `npx playwright install chromium`. `npm run doctor -- --auth --live` проверяет только настройки Auth без требования AI/серверного ключа. **Для облачного выпуска после verify выполни отдельный `npm run build` с заполненным env.** GitHub Actions использует тот же verify; удалённый CI запускается после твоего push.

Профиль теперь использует версию: устаревшее сохранение получает 409, текст остаётся в форме. Применить миграцию `202609080003_profile_versions.sql` обязательно до запуска обновлённого API. Если ответ БД потерялся после записи, новое фото сохраняется в Storage; возможный лишний объект не удаляется вслепую. Фоновая очистка таких объектов не реализована.

В локальном preview используются Web Locks, когда браузер их предоставляет, и сравнение снимка до и после запроса. Для надёжной работы нескольких вкладок открывай localhost или HTTPS в современном браузере с Web Locks. В окружениях без Web Locks проверка снимка снижает риск конфликта, но не является атомарной блокировкой между процессами. Облачное сохранение защищает PostgreSQL.

Шрифты Geist Sans/Mono берутся из установленного пакета `geist`; скачивание Google Fonts при сборке больше не требуется. Перенос исходников, Windows/OneDrive и commit/push описаны в `docs/VSCODE.md`.
